What this run proves

  • The same spec works on a bug-hunt store by swapping only the store config: baseURL, shop id, variant, no password, CAD, Canadian address.
  • The benchmark test identity works on any store. The check is on the email pattern (app/models/benchmarkable.rb), not the shop, so the fixed email code and simulated SMS apply here too.
  • Under treatment a brand-new email lands in Pay checkout with no phone entry and no SMS code (frame at 9.8 s), matching the E2E-store run.
  • Address, card, Pay now and order confirmation work end to end on a store outside Core's E2E allowlist, with real production captcha behaviour.

What it does not prove

  • Only the happy path, entered through the express-wallet Shop Pay button. The bug-hunt doc lists this store under "direct payment"; that entry point is not exercised here.
  • The store is on pod 233. The e2e framework warns that E2E shops must be on pod 21 and says the warning will become an error, so this spec should stay local, not be committed.
  • Benchmark identities get a fixed email code and simulated SMS, so real OTP delivery is out of scope.
  • One run, one browser. No concurrency or second-device behaviour exercised.
