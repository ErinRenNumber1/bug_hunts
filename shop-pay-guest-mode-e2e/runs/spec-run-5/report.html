What this run proves

  • On spi-high-aov, a guest-mode buyer sees no Installments address banner on an empty shipping form, nor after entering a valid US address. The 2026-09-23 fix (PR 1021476) holds under guest mode.
  • Installments underwriting asks for an SMS code to the shipping phone, so the phone verification guest mode skips is recovered before any payment plan is offered.
  • After identity verification, the Affirm agreement request fails with 422 checkout_error on both attempts today (14:23Z and 14:39Z), and the buyer is told to pay in full. Case 4's expected outcome, "the order completes", was not reached.

What it does not prove

  • The 422 body is shop-server's generic wrapper for a non-2xx from the upstream agreements API (engines/pay/app/services/pay/installments/agreements_api.rb, handle_response). The trace has no upstream detail; the server logs an agreements_call debug event with the upstream HTTP status.
  • Separated the same day: John's tracked guest-mode spec on spi-e2e-testing (USD 65) passed at 15:14Z with the agreement returning 202; spec 5 with the USD 100 product on spi-high-aov failed with the same 422 at 15:17Z; and a control spec on spi-high-aov with guest mode forced to control and an ordinary email, phone and SMS-code sign-up failed with the same 422 at 15:21Z. The failure follows the store, not guest mode or the amount.
