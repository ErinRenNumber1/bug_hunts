Reading the result

What this run proves

  • A buyer created through guest mode can sign in to a different store's customer account through Sign in with Shop. Shop asks for an email code and then an SMS code to the part A shipping phone, which verifies that phone.
  • After that sign-in, opening a cart permalink on reinis-test-store lands the buyer directly in Shop Pay checkout with address and card vaulted, and no further email, phone or SMS step.
  • All three parts run in one browser, so this is one person continuing, not a competing browser. Every expectation is a hard assertion and the run passed.

What it does not prove

  • That the phone code in part B is what lets part C skip verification is the working explanation, not something this run shows on its own. The popup cannot be completed without the phone code, so a run without it is not possible through this path.
  • The direct jump from the cart permalink into Pay checkout happens because the customer account session is present. Confirmed as the intended experience on 2026-09-30; runs 4 to 6 of this spec had recorded it as a deviation.
  • The guest-mode override header is sent for the whole run, including parts B and C. An existing buyer with an order is outside the experiment's gates, so it should not change them.
  • Full run 37.2 s. Store lucasmrichtest is on pod 233 (framework warns E2E shops must be on pod 21), so this spec stays local.
  • Benchmark identity: fixed email code and simulated SMS; one run, one browser.
