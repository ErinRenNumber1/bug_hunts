What this run proves

  • A buyer created through guest mode can sign in to a different store's customer account through Sign in with Shop, but Shop asked for an email code and then an SMS code to the unverified part A shipping phone, not the email code alone.
  • After that sign-in, opening a cart permalink on reinis-test-store lands the buyer directly in Shop Pay checkout with address and card vaulted, and no phone or SMS verification at all.
  • All three parts run in one browser, so this is one person continuing, not a competing browser.

What it does not prove

  • Why part C skipped SMS is inferred, not shown: the phone code accepted in part B most likely verified the shipping phone, so the buyer was already phone-verified when Shop Pay was entered. A run that avoids the part B phone step would settle it, but the popup could not be completed without it.
  • The direct jump from the cart permalink into Pay checkout happens because the customer account session is present; whether that is the intended experience for a guest-mode buyer is a product question, not something this run decides.
  • The guest-mode override header is sent for the whole run, including part C. An existing buyer with an order is outside the experiment's gates, so it should not change part C.
  • Playwright verdict is Failed because of the two soft expectations above; every step otherwise completed. Store lucasmrichtest is on pod 233 (framework warns E2E shops must be on pod 21), so this spec stays local.
  • Benchmark identity: fixed email code and simulated SMS; one run, one browser.
