Reading the result

What this run proves

  • The guest session is cookie-backed: a fresh server render of /shoppay recognises the unverified, phoneless buyer without re-authentication.
  • A reload from the same browser is not treated as a competing session; address save and Pay now still succeed afterwards.
  • Same store, variant and override as run 2, so the only new variable is the reload.

What it does not prove

  • Reload only. Closing the tab and reopening /shoppay, or opening it in a second tab, is not exercised.
  • Moment timestamps for the reload frames are estimates; check the shots folder if a caption does not match its still.
  • Store is on pod 233; the e2e framework warns E2E shops must be on pod 21, so this spec stays local.
  • Benchmark identity: fixed email code and simulated SMS; one run, one browser.
